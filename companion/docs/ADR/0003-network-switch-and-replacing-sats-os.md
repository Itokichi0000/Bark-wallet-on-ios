# ADR-0003: Signet / Mainnet の切り替えと、Sats-OS の TestFlight 枠への上書き

- 状態: 採用（2026-11-24、所有者の明示的な指示）
- 背景: 当初は Signet 専用・別バンドル ID（ADR-0001）。所有者から「Signet と本番をスイッチ一つで切り替え」
  「既存の TestFlight に完全に上書きして配信」の指示があった。設計書は Mainnet を明示承認まで禁じており、これがその承認にあたる。
- 決定:
  1. バンドル ID を `com.itokichi0000.satsos` にし、既存の Sats-OS の枠に配信する。版は 2.0.0。
     SwiftUI 版の TestFlight ワークフローは手動実行のみにした。
  2. ネットワークは起動時に一度だけ決める（`src/config/network.ts`）。既定は Signet。設定画面の切り替えは
     警告の確認 → 端末認証 → ウォレットを閉じる → アプリ再起動。動作中のウォレットを別ネットワークに向け直すことはしない。
  3. シード・DB・未確定送金・バックアップ・設定はネットワークごとに別（`bcw.<network>.*`、`bark-<network>/`）。
     Signet のシードが本番で使われることはない。バックアップの鍵にもネットワーク名が入る。
  4. Mainnet の値（`Network.Bitcoin`、本番エンドポイント）は 3 ファイルにだけ存在し、単体テストで固定している。
- 結果と注意:
  - **このアプリは実機で未検証のまま本番の資金を扱えるようになる。** 画面に常時 MAINNET 表示と警告を出すが、少額に限ること。
  - 更新した端末では、SwiftUI 版 Sats-OS のウォレットは表示されない（データは端末に残るが、このアプリは読まない）。
    引き継ぐには、更新前に Sats-OS でシードを控え、本番に切り替えてから「シードだけで復元」を使う（サーバーの協力が必要、履歴は戻らない）。
  - 元に戻すには TestFlight で以前のビルドを入れ直すか、`testflight.yml` を手動実行する。
