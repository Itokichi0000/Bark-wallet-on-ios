# セキュリティモデル

## 層の分離

```
画面 (app/) → WalletService → WalletAdapter → Bark SDK
                    │
                    └→ EventBus → AvatarOrchestrator（表示の合図だけ）
```

- Bark SDK に触るのは `src/infrastructure/bark/BarkWalletAdapter.ts`（とバックアップの `readDatadirInfo`）だけ。
- `src/game/` と `src/voice/` は、シード保管・SDK・送金実行・バックアップを import しない（単体テストで検査）。
- アバターはイベントを読むだけで、ウォレットの状態を持たず、送金を起こす経路がない。

## シード

- 保管: iOS Keychain / Android Keystore（`expo-secure-store`, `WHEN_UNLOCKED_THIS_DEVICE_ONLY`）。上書きは拒否。
- 表示: 設定 → 端末認証 → 専用画面。画面収録・スクリーンショットを抑止。自動コピーなし。
- ログ・解析・クリップボード・読み上げ・LLM には渡さない。アプリ内に `console.*` 呼び出しがないことをテストで検査。
- 既知の限界: JS の文字列はメモリから確実に消せない。復元画面の入力欄は OS のキーボード学習を無効化しているが完全ではない。

## 送金

- 確認画面に ネットワーク / 方式 / 宛先全文 / 金額 / 手数料 / 合計 / 送金後残高 を表示し、最後の操作は必ず利用者。
- 状態機械（`sendReducer`）は review → 利用者の確定 → 端末認証 を経ないと submitting に入れない。
- SDK を呼ぶ前に操作を永続化。同じ operationId は二度送らない。送金中は別の送金を始められない。
- SDK 呼び出しが例外・タイムアウトで終わったら結果は **不明**。自動再送はせず、履歴と残高の証拠で照合する。
  「送られていない」と結論するのは、同期が成功し、該当する記録がなく、処理中の残高もゼロのときだけ。
- 成功の演出は、ウォレットの記録で成功が確認できたあとだけ。

## 話しかける機能

- 決め打ちの意図パーサ＋方針エンジン。出力は「話す / 画面を開く / 下書きを開く」の 3 種類のみで、
  送金を確定する種類が型として存在しない。宛先は発話から取り込まない。
- 秘密鍵・シードに触れる発話は、内容にかかわらず拒否の定型文を返す。

## ネットワーク

- Signet 固定。DB が別ネットワークなら開かない。別ネットワークのバックアップは復元しない。
- 外部への通信先は Ark サーバーと Esplora のみ。解析 SDK なし。
